# Plan 09-02: Manual Attendance Correction & Audit History Suite

## Phase: Phase 9 - Admin Dashboard, Reports & Audit Log
## Plan ID: 09-02
## Objective: Build `AttendanceCorrection` audit log model, admin manual correction modal, atomic correction service, and audit history viewer.

---

### Key Deliverables:
1. `apps/reports/models.py`:
   - `AttendanceCorrection`: `school` (FK), `attendance` (FK), `performed_by` (FK User), `old_status`, `new_status`, `old_check_in_time`, `new_check_in_time`, `old_check_out_time`, `new_check_out_time`, `reason` (mandatory), `created_at`.
2. `apps/reports/services.py`:
   - `ReportService.correct_attendance(...)` atomic correction pipeline.
3. `apps/reports/views.py`:
   - `AttendanceCorrectView` (`/reports/correct/<int:pk>/`) handling correction form submit.
   - `AttendanceAuditHistoryView` (`/reports/audit/<int:pk>/`) rendering correction audit log history drawer/modal.
4. Unit Test Suite (`apps/reports/tests.py`):
   - Dashboard KPI metrics calculations (present, late, absent, half-day).
   - Manual correction creates `AttendanceCorrection` audit log record and updates `AttendanceLog`.
   - Empty correction reason string is rejected.
   - CSV export generation.

---

### Verification:
- Run unit test suite `python manage.py test apps.reports.tests`.
- Perform a manual correction on an attendance log in browser with reason and verify audit record created.
