# Plan 07-03: Attendance Record State Machine, Cooldown Lock & Edge Cases

## Phase: Phase 7 - Face-Based Check-In & Check-Out Engine
## Plan ID: 07-03
## Objective: Build `AttendanceLog` model, Check-In / Check-Out state machine transition engine, 30-second server-side scan cooldown lock, and edge case handlers.

---

### Key Deliverables:
1. `apps/attendance/models.py`: `AttendanceLog` model:
   - Fields: `school` (FK), `faculty` (FK), `date` (DateField, `timezone.localdate()`), `check_in_time` (TimeField), `check_out_time` (TimeField, nullable), `status` (ChoiceField: PRESENT/LATE/HALF_DAY), `device_info` (CharField), `created_at`, `updated_at`.
   - `Meta`: `unique_together = ('school', 'faculty', 'date')`.
2. `apps/attendance/services.py`: `AttendanceStateMachine` service:
   - State Machine logic for today's date (`today = timezone.localdate()`):
     - **No record today**: Create new `AttendanceLog` with `check_in_time = current_time`.
     - **Record exists without check_out**: Update `check_out_time = current_time`.
     - **Record exists with check_out**: Update `check_out_time = current_time` to latest timestamp.
   - Dual-layer server-side 30-second cooldown check: Reject duplicate scans occurring within 30s of previous scan for same faculty (`HTTP 429 / Cooldown Response`).
3. Edge Case Handling:
   - Unrecognized face response payload.
   - Non-active / deactivated faculty scan rejection.
   - Atomic database locking (`select_for_update`) preventing race conditions during rapid camera frames.

---
