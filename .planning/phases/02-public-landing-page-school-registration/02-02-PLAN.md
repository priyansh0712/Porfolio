# Plan 02-02: School Self-Registration & Onboarding Flow

## Phase: Phase 2 - Public Landing Page & School Registration
## Plan ID: 02-02
## Objective: Build school self-registration form, validation logic, tenant creation service, and admin account initialization.

---

### Key Deliverables:
1. `apps/tenants/models.py`: `School` (Tenant) model storing school metadata (`name`, `subdomain`, `contact_email`, `is_active`, `created_at`).
2. `apps/tenants/forms.py`: `SchoolRegistrationForm` validating school details, subdomain syntax (alphanumeric/hyphen), reserved subdomain checks (`www`, `admin`, `api`, `app`, `mail`), and unique constraints.
3. `apps/tenants/services.py`: `SchoolRegistrationService` executing atomic transaction to create School record and initial School Admin user account.
4. `apps/public/views.py`: `SchoolRegistrationView` processing form submissions and `RegistrationSuccessView` providing tenant redirect instructions.
5. `templates/public/register.html`: Clean form template styled with Tailwind CSS for self-registration.
6. `templates/public/register_success.html`: Confirmation screen with subdomain link (`school.ourapp.com`) and next-step guidance.

### Implementation Details:
- **Subdomain Validation**: Ensure subdomain is lowercase, valid slug, minimum 3 chars, not reserved, and strictly unique.
- **Atomic Creation**: Use `@transaction.atomic` in `SchoolRegistrationService` so school and admin user creation succeed or roll back together.
- **Admin Password**: Hash password using Django standard password hashers.
- **User Feedback**: Inline form error messages for invalid subdomains, duplicate emails, or weak passwords.
