# Plan 02-02: Scoped Views, Transfer Workflow, Student Hub & Student Portal Apple UI

## Objective
Implement role-scoped views and controllers for Student CRUD (enforcing Class Teacher boundaries and locked GR numbers), create the Principal Transfer Request approval workflow, build Apple Design System responsive templates (`templates/students/`), and implement the view-only Student Portal with full automated test coverage.

---

## Tasks

### Task 1: Student Scoped Views & Permission Mixins
- **Files**: `apps/students/views.py`, `apps/students/mixins.py`
- **Details**:
  - `SchoolStaffRequiredMixin`: Permits School Admin and Class Teachers to access the student management module.
  - `StudentRequiredMixin`: Permits only authenticated students with `role == User.Role.STUDENT`.
  - `StudentHubView`:
    - Displays active academic year student roster with search (GR No, Name, Roll No), Standard filter, Division filter, and Active/Inactive filter.
    - If user is Class Teacher: scopes query to students in their assigned division (`ClassTeacherAllocation`), restricts filter dropdowns.
  - `StudentCreateView`:
    - School Admin can select any standard & division and enter GR Number.
    - Class Teacher can create student only in their assigned division; enters initial GR Number.
  - `StudentUpdateView`:
    - School Admin can update all fields including GR Number.
    - Class Teacher can update fields, but GR Number field is locked (read-only) and immutable.
  - `StudentDeleteView`: Soft-deactivates student (`is_active=False`). School Admin only.
  - `StudentTransferRequestCreateView`: Allows Class Teacher to request transfer to another division.
  - `StudentTransferApproveView` & `StudentTransferRejectView`: 1-click actions for School Admin.
  - `StudentPortalView`: Read-only student dashboard displaying:
    - Personal info (GR No, Roll No, DOB, Blood Group, Guardian Contact).
    - Class Teacher card with photo/contact.
    - List of enrolled subjects and respective subject teachers.

### Task 2: URL Routing & Tenant Middleware
- **Files**: `apps/students/urls.py`, `config/urls.py`, `apps/accounts/middleware.py`, `apps/accounts/views.py`
- **Details**:
  - Register `apps.students.urls` under `/students/`.
  - Add `'/students/'` to `TENANT_SCOPED_PREFIXES` in `apps/accounts/middleware.py`.
  - Update `TenantDashboardView` in `apps/accounts/views.py` to route `User.Role.STUDENT` to `StudentPortalView`.

### Task 3: Apple Design System Templates
- **Files**:
  - `templates/students/student_hub.html` (Main hub layout with tabs/filters)
  - `templates/students/partials/tab_students.html` (Responsive data table with search & pill badges)
  - `templates/students/partials/tab_transfers.html` (Transfer requests table with status pills)
  - `templates/students/partials/modals.html` (Apple modals for Add Student, Edit Student, Request Transfer, and Delete Confirmation)
  - `templates/students/student_portal.html` (Dedicated student view with profile, Class Teacher banner, and subjects grid)
  - `templates/components/navbar_admin.html` (Add "Students" navigation link)
  - `templates/components/navbar_faculty.html` (Add "My Class" student link)
- **Details**:
  - Strictly adhere to `SF Pro`, `#f5f5f7` canvas, `#ffffff` cards, `#0066cc` buttons, soft pastel status badges, and 0 browser native `confirm()` popups.

### Task 4: Automated Integration Tests & Verification
- **Files**: `apps/students/tests.py`
- **Details**:
  - Test School Admin full CRUD and GR Number edit capabilities.
  - Test Class Teacher scoped CRUD (cannot view/edit other divisions, GR Number immutable on edit).
  - Test Student Transfer Request creation, approval, and rejection.
  - Test Student Portal login and read-only view.
  - Verify tenant isolation across all endpoints.
  - Ensure `tearDown()` clears tenant context (`set_current_tenant(None)`).
