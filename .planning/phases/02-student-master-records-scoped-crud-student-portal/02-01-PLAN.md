# Plan 02-01: Core Student Models, Role.STUDENT Authentication & Service Layer

## Objective
Establish the `apps.students` Django application, add `Role.STUDENT` to the custom User model with updated check constraints, implement the dual-mode authentication backend (supporting Email for Staff and GR Number for Students with default password `Admin@123`), and build `apps.students.services.StudentService` for atomic student provisioning and transfer operations.

---

## Tasks

### Task 1: Expand User Role with `Role.STUDENT`
- **Files**: `apps/accounts/models.py`
- **Details**:
  - Add `STUDENT = 'STUDENT', 'Student'` to `User.Role`.
  - Update `CheckConstraint` in `apps/accounts/models.py` to allow `STUDENT` with non-null `school`.
  - Generate and apply Django migration `apps/accounts/migrations/0002_user_role_student.py` (or next sequence).

### Task 2: Create `apps.students` App and Data Models
- **Files**: `apps/students/__init__.py`, `apps/students/apps.py`, `apps/students/models.py`, `config/settings/base.py`
- **Details**:
  - Register `'apps.students.apps.StudentsConfig'` in `LOCAL_APPS`.
  - Create `Student` model with fields:
    - `school` (FK `tenants.School`)
    - `user` (OneToOneField `accounts.User`, null=True, blank=True)
    - `gr_number` (CharField, db_index=True)
    - `roll_number` (PositiveIntegerField, null=True, blank=True)
    - `full_name` (CharField)
    - `dob` (DateField, null=True, blank=True)
    - `gender` (CharField choices MALE/FEMALE/OTHER)
    - `blood_group` (CharField choices)
    - `guardian_name`, `guardian_phone`, `emergency_contact`, `address`
    - `academic_year` (FK `academics.AcademicYear`)
    - `standard` (FK `academics.Standard`)
    - `division` (FK `academics.Division`)
    - `admission_date` (DateField)
    - `is_active` (BooleanField, default=True)
  - Add `UniqueConstraint(fields=['school', 'gr_number'], name='unique_school_student_gr_number')`.
  - Add `UniqueConstraint(fields=['school', 'academic_year', 'division', 'roll_number'], condition=Q(roll_number__isnull=False, is_active=True), name='unique_active_roll_per_division_year')`.
  - Create `StudentTransferRequest` model with fields:
    - `school`, `student`, `from_division`, `to_division`, `requested_by` (Faculty), `status` (PENDING/APPROVED/REJECTED), `reason`, `reviewed_by`, `reviewed_at`, `rejection_reason`.
  - Generate and run migrations for `apps.students`.

### Task 3: Dual-Identifier Authentication Backend
- **Files**: `apps/accounts/backends.py`, `apps/accounts/forms.py`, `config/settings/base.py`
- **Details**:
  - Implement `TenantAuthBackend(ModelBackend)`:
    - If identifier contains `@`: authenticate by `email`.
    - If identifier has no `@`: look up `Student` by `gr_number=identifier, school=tenant, is_active=True`, authenticate against `student.user`.
  - Configure `AUTHENTICATION_BACKENDS = ['apps.accounts.backends.TenantAuthBackend', 'django.contrib.auth.backends.ModelBackend']`.
  - Update `TenantLoginForm` username field label to `'Email Address / GR Number'` and update validation.

### Task 4: Student Service Layer
- **Files**: `apps/students/services.py`
- **Details**:
  - Implement `StudentService`:
    - `create_student(school, academic_year, standard, division, gr_number, full_name, roll_number=None, dob=None, gender='MALE', blood_group='', guardian_name='', guardian_phone='', emergency_contact='', address='', admission_date=None)`:
      - Validates GR uniqueness per school.
      - Creates linked `User` with username `gr_{school.code}_{gr_number}`, email `gr_{school.code}_{gr_number}@student.local`, role `Role.STUDENT`, default password `Admin@123`.
      - Creates `Student` record.
    - `update_student(student, allow_gr_edit=False, **fields)`:
      - Updates student details; updates GR only if `allow_gr_edit=True`.
    - `soft_delete_student(student)`: sets `is_active=False` and deactivates linked `user`.
    - `request_transfer(student, to_division, requested_by, reason)`: creates `StudentTransferRequest`.
    - `approve_transfer(transfer_request, reviewed_by)`: updates student's standard & division atomically, marks status `APPROVED`.
    - `reject_transfer(transfer_request, reviewed_by, rejection_reason)`: marks status `REJECTED`.

### Task 5: Unit Tests for Models, Auth & Service
- **Files**: `apps/students/tests.py`
- **Details**:
  - Test tenant isolation and uniqueness constraints.
  - Test student user provisioning and GR number authentication.
  - Test student transfer approval/rejection logic.
  - Clean up tenant context with `set_current_tenant(None)` in `tearDown()`.
