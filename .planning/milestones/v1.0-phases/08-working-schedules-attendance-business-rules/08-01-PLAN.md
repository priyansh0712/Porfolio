# Plan 08-01: WorkingSchedule Models, Auto-Initializer & Admin Settings UI

## Phase: Phase 8 - Working Schedules & Attendance Business Rules
## Plan ID: 08-01
## Objective: Build `WorkingSchedule` and `HolidayException` models, default tenant schedule initializer, and Apple-aesthetic Admin Settings UI (`/settings/schedule/`).

---

### Key Deliverables:
1. `apps/schedules/models.py`:
   - `WorkingSchedule`: `school` (FK), `day_of_week` (0=Mon..6=Sun), `is_working_day`, `start_time`, `end_time`, `grace_period_minutes`. Unique constraint `(school, day_of_week)`.
   - `HolidayException`: `school` (FK), `date`, `description`, `is_recurring_yearly`. Unique constraint `(school, date)`.
2. `apps/schedules/services.py`:
   - `ScheduleService.initialize_default_schedules(school)` seeding 7 day records for new tenant.
3. `apps/schedules/views.py`:
   - `ScheduleSettingsView` (`/settings/schedule/`) extending `SchoolAdminRequiredMixin`.
4. `templates/schedules/schedule_settings.html`:
   - Apple-style day-by-day tabbed forms, grace period inputs, and holiday exception table with add/delete forms.

---

### Verification:
- Register new school tenant or run initializer to confirm 7 `WorkingSchedule` records are created.
- Access `/settings/schedule/` in browser as School Admin and update working hours & grace period.
