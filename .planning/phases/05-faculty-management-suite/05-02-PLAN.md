# Plan 05-02: School Admin Faculty Management UI, 3-Layer Security Views, and Automated Test Suite

## Objective
Deliver tenant-scoped Faculty CRUD views (List, Create, Edit, Toggle Status) protected by the 3-Layer Security architecture, construct an Apple Design System table UI with real-time search, department filter, status badges, and modal drawer, wire up dashboard navigation, and build a comprehensive automated test suite (`tests_faculty.py`).

## Tasks

### Task 1: Create Tenant-Scoped Faculty Views in `apps/faculty/views.py`
- `FacultyListView(SchoolAdminRequiredMixin, ListView)`:
  - Renders `templates/faculty/faculty_list.html`.
  - Scopes queryset: `Faculty.objects.filter(school=self.request.tenant)`.
  - Pass departments list in context (`queryset.values_list('department', flat=True).distinct()`).
- `FacultyCreateView(SchoolAdminRequiredMixin, CreateView)`:
  - Processes `FacultyForm` via POST / AJAX modal.
  - Calls `FacultyService.create_faculty(self.request.tenant, form.cleaned_data)`.
  - Returns JSON success or redirects with toast message.
- `FacultyUpdateView(SchoolAdminRequiredMixin, UpdateView)`:
  - Scopes queryset: `Faculty.objects.filter(school=self.request.tenant)`. Explicit 3-layer security check.
  - Updates faculty and synchronizes linked user via `FacultyService.update_faculty()`.
- `FacultyToggleStatusView(SchoolAdminRequiredMixin, View)`:
  - POST-only endpoint: toggles `is_active` status for target faculty (explicitly verified `school=request.tenant`). Returns JSON status.

### Task 2: Configure URL Routing in `apps/faculty/urls.py` & `config/urls.py`
- Add app `faculty` namespace in `urls.py`:
  - `""` → `FacultyListView` (`name='list'`)
  - `"create/"` → `FacultyCreateView` (`name='create'`)
  - `"<int:pk>/edit/"` → `FacultyUpdateView` (`name='edit'`)
  - `"<int:pk>/toggle-status/"` → `FacultyToggleStatusView` (`name='toggle_status'`)
- Include `apps.faculty.urls` in `config/urls.py` under path `'faculty/'`.

### Task 3: Build Apple Design System UI Templates
- `templates/faculty/faculty_list.html`:
  - Inherits from `base.html`.
  - Apple Header: Page title "Faculty Directory", total count badge, and `+ Add Faculty` primary blue pill button (`#0066cc`).
  - Search & Filter Toolbar: Real-time JS search input (name, email, code), Department dropdown filter, Status pills (`All`, `Active`, `Inactive`).
  - Apple Data Table: `#ffffff` surface, 1px hairline border, rounded-2xl container.
  - Columns: Faculty Info (Avatar initial, Name, Email), Employee Code, Department & Designation, Active Status (`Active` green, `Inactive` gray), Face Status (`Pending` amber pill), Actions (Edit modal trigger, Toggle Active button).
  - Empty state with clean graphic illustration.
- `templates/faculty/includes/faculty_form_modal.html`:
  - Apple frosted glass modal (`backdrop-filter: blur(20px)`), smooth slide-up animation.
  - Form fields for First Name, Last Name, Email, Phone, Employee Code (with auto-generate helper note), Department, Designation.
- Update `templates/accounts/dashboard.html` to add direct link to Faculty Directory in Quick Actions / navigation.

### Task 4: Build Automated Test Suite in `apps/faculty/tests_faculty.py`
- Test 1: **Tenant Query Scoping** — School A admin sees only School A faculty; School B admin sees only School B faculty.
- Test 2: **Cross-Tenant ID Manipulation Blocked** — School A admin attempting to edit/toggle School B faculty ID receives HTTP 404 / 403 Forbidden.
- Test 3: **Faculty Creation & Linked User Prototyping** — Creating faculty provisions `User` with `role=FACULTY`, `school=tenant`, `is_active=True`, and unusable password (`set_unusable_password()`).
- Test 4: **Faculty Dashboard Login Restriction** — Attempting to log into `/login/` with a `FACULTY` user account is rejected by `TenantAwareAuthBackend` / `TenantLoginView`.
- Test 5: **Sequence Counter Concurrency & Auto-Code** — `FacultyCodeService` auto-generates `GREENWOOD-FAC-001`, `GREENWOOD-FAC-002` correctly.
- Test 6: **Status Toggle & SET_NULL Integrity** — Toggling status disables linked user. Deleting linked user sets `faculty.user` to `None` without removing the `Faculty` record.

## Verification Criteria
- All tests in `python manage.py test apps.faculty.tests_faculty --settings=config.settings.local` pass 100%.
- System check `python manage.py check --settings=config.settings.local` reports 0 errors.
- Visual inspection on `http://greenwood.localhost:8000/faculty/` verifies crisp Apple Design System styling.
